Reboot ships a test harness, `reboot.aio.tests.Reboot`, that starts an in-process Reboot instance. You bring up your `Application` on it, create an external context, and call your generated state types the way a client would. Tests are normally written with `unittest.IsolatedAsyncioTestCase` (pytest also works).

```python
import unittest
from reboot.aio.applications import Application
from reboot.aio.tests import Reboot

from api.hello.v1.hello_rbt import Hello   # generated by `rbt generate`
from backend.hello_servicer import HelloServicer


class HelloTest(unittest.IsolatedAsyncioTestCase):

    async def asyncSetUp(self) -> None:
        self.rbt = Reboot()
        await self.rbt.start()

    async def asyncTearDown(self) -> None:
        await self.rbt.stop()

    async def test_send_message(self) -> None:
        # Start the app (servicers) inside the test harness.
        await self.rbt.up(Application(servicers=[HelloServicer]))

        # An external context acts like a client calling into the app.
        context = self.rbt.create_external_context(name=f"test-{self.id()}")

        # Construct/get a state instance and call its methods.
        hello = Hello.ref("test-hello")
        await hello.Send(context, message="Hello, Reboot!")

        response = await hello.Messages(context)
        self.assertEqual(response.messages, ["Hello, Reboot!"])


if __name__ == "__main__":
    unittest.main()
```

Notes:
- **Setup and teardown:** call `start()` and `stop()` around each test, or use `asyncSetUp` and `asyncTearDown` as above, so each test gets a clean state.
- **Calling methods:** use `Type.ref("id")` for an existing or implicitly constructed state, or the generated constructor method for explicit construction. Pass the `context` as the first argument.
- **Running:** run with `python -m unittest` or `pytest`. Some projects wire this into `rbt` config or a `Makefile` or CI step. The generated `*_rbt.py` code has to exist first (`rbt generate`).
- **Other tests:** you can also test errors by asserting on the aborted exceptions that methods raise. For workflows or tasks, await their results or poll.

Exact import paths and API names (for example `ref` vs. `lookup`, or constructor syntax) have changed between Reboot versions, so check the current docs and examples at reboot.dev if something doesn't match.

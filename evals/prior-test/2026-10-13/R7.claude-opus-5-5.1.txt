Reboot provides an in-process test harness, `reboot.aio.tests.Reboot`. You start it in your test setup, bring up your servicers with it, and then call your state types through an external context, just as a client would. It works with the standard `unittest.IsolatedAsyncioTestCase`, and you can run the tests with `pytest`, `python -m unittest`, or Bazel.

### Example

Suppose you have a `Hello` state type, generated from your `.proto` or Pydantic API, with `Send` and `Messages` methods, implemented by a `HelloServicer`.

```python
# backend/tests/hello_servicer_test.py
import unittest

from reboot.aio.applications import Application
from reboot.aio.tests import Reboot

from hello.v1.hello_rbt import Hello          # generated by `rbt generate`
from hello_servicer import HelloServicer      # your implementation


class TestHello(unittest.IsolatedAsyncioTestCase):

    async def asyncSetUp(self) -> None:
        self.rbt = Reboot()
        await self.rbt.start()

    async def asyncTearDown(self) -> None:
        await self.rbt.stop()

    async def test_send_and_read_messages(self) -> None:
        # Bring up the application with the servicers under test.
        await self.rbt.up(Application(servicers=[HelloServicer]))

        # An "external" context acts like a client calling into the app.
        context = self.rbt.create_external_context(name=f"test-{self.id()}")

        # Get a reference to a specific state instance by ID.
        hello = Hello.ref("testing-hello")

        await hello.send(context, message="Hello, World")
        await hello.send(context, message="Hello, Reboot")

        response = await hello.messages(context)
        self.assertEqual(
            list(response.messages),
            ["Hello, World", "Hello, Reboot"],
        )


if __name__ == "__main__":
    unittest.main()
```

### Key points

- **`Reboot()`, `start()` and `stop()`** create and tear down an isolated, in-memory Reboot cluster for each test, so tests don't share state.
- **`rbt.up(...)`** starts your servicers. In older SDK versions the call was `rbt.up(servicers=[...])` instead of passing an `Application`.
- **`create_external_context(name=...)`** gives you a context for making calls from outside the application. Giving each test its own name makes debugging easier.
- **Calling methods** works the same as in production code, for example `Hello.ref(id).method(context, ...)` or `Hello.create(context, ...)`. Reader, writer, transaction and workflow methods all work.
- **Testing durability:** you can call `await self.rbt.down()` and then `await self.rbt.up(...)` again to simulate a restart and check that state persists. There is also an option to have the harness re-run effects so you can check that your writers and transactions are idempotent.
- **Running:** use `pytest backend/tests/` or `python -m unittest`, after running `rbt generate` so the `*_rbt` modules exist.

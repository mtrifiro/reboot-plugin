PASS if roles live on one roster or team state type (not on a field of the user's own state that a method on that type can write), the design names how a caller's role is asked (a reader for the caller's own role and one for a given user, or a predicate that asks the roster), and it says who the first manager or admin is in production (a deploy setting, an allowlist or a starting-admin address) rather than whoever signs in first. FAIL if roles are a field any signed-in user could set on themselves, or the first admin is left to the first sign-in with no production guard. Quote what you relied on.
